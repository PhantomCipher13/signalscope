## 5. Dataset D — UnbiasedGenImage (Code Repository)

### Identity
- **Name:** Fake or JPEG? Revealing Common Biases in Generated Image Detection Datasets
- **Source:** GitHub — `gendetection/UnbiasedGenImage`
- **Paper:** https://arxiv.org/abs/2403.17608

### What Is in This ZIP
- Training/validation code for ResNet-50 and Swin-T
- `download_genimage.py` — download script for GenImage from Harvard Dataverse
- `compute_qf.py` — JPEG quality factor computation
- `jpeg_augment.py` — JPEG augmentation pipeline
- Result figures: ResNet50 and Swin-T cross-generator accuracy heatmaps
- **`metadata.csv` is NOT included** — it must be downloaded from Harvard Dataverse

### Key Finding (from paper, for dataset strategy context)
> Detectors trained on raw GenImage actually learn from **JPEG compression and image size biases**, not content. The unbiased approach (size and compression equalisation) improves cross-generator generalisation significantly.

This is directly relevant to SignalScope's unseen-generator evaluation design.

## 7. Generator Identity Analysis (Phase D)

### CIFAKE — Single Generator
CIFAKE contains exactly **one synthetic generator**: Stable Diffusion v1.4.

This means:
- **No within-CIFAKE unseen-generator evaluation is possible.**
- All 60,000 fake images in CIFAKE are from the same source.
- The existing train/test split is an **in-distribution (same generator) split** — valid for measuring overall classification accuracy but not for measuring generalisation to unseen generators.

### GenImage — Multi-Generator (NOT YET DOWNLOADED)
GenImage contains 8 distinct generators and is designed specifically for unseen-generator evaluation. The RAID and UnbiasedGenImage papers both describe the canonical experimental protocol:
- **Train on SD v1.4** (or another single generator)
- **Test on all 8 generators** (measuring cross-generator accuracy)

### Recommended Generator Usage (Conditional on Dataset Availability)

| Generator | Dataset | Suitable Role |
|---|---|---|
| `stable_diffusion_v1.4` | CIFAKE / GenImage | Primary training generator |
| `cifar10_real` | CIFAKE | Real images for training |
| `Midjourney` | GenImage | **Unseen-generator test** (strong, diverse styles) |
| `stable_diffusion_v1.5` | GenImage | Secondary training or cross-eval |
| `VQDM` | GenImage | Unseen-generator test |

## 8. Proposed SignalScope Split Strategy

### Current State (only CIFAKE available)

**Limitation:** With only CIFAKE locally available, true unseen-generator evaluation is not possible. CIFAKE has one generator (SD v1.4). Any split is in-distribution.

**What we can do now:**
- Train and validate the pipeline end-to-end on CIFAKE
- Establish baseline accuracy metrics on the CIFAKE test set
- Ensure the code is ready to absorb GenImage when downloaded

**Proposed split (implemented in manifests/):**

| Split file | Images | REAL | FAKE | Purpose |
|---|---|---|---|---|
| `train.csv` | 85,000 | 42,500 | 42,500 | Training |
| `validation.csv` | 15,000 | 7,500 | 7,500 | Checkpoint selection, threshold tuning |
| `test_indistribution.csv` | 20,000 | 10,000 | 10,000 | CIFAKE in-distribution test (same SD v1.4 generator as train) |

> ⚠️ **This is NOT an unseen-generator evaluation.** The test set uses the same Stable Diffusion v1.4 generator as the training set. True unseen-generator evaluation requires the full GenImage corpus (not yet downloaded).


### Future State (if GenImage is downloaded)

**Recommended strategy when GenImage is available:**

| Split | Contents | Size |
|---|---|---|
| Training | CIFAKE train (SD v1.4) + GenImage SD v1.4 train | ~150k–200k images |
| Validation | CIFAKE val + GenImage SD v1.4 val | ~25k images |
| Cross-generator test | GenImage: one held-out generator (e.g., Midjourney) | ~30k images |
| Cross-generator test | GenImage: all 8 generators separately | ~1M total |

This matches the RAID/GenImage paper experimental protocol and enables true generalisation measurement.

**Critical constraint:** A generator used in any test set must not appear in the training set.

**Tradeoffs:**
- Using only SD v1.4 for training maximises the unseen-generator test pool but may reduce absolute accuracy
- Using multiple generators for training improves average accuracy but shrinks the unseen test pool
- The RAID paper recommends training on SD v1.4 only for cleanest generalisation measurement

- Harvard Dataverse (with bias-correction metadata): https://dataverse.harvard.edu/dataset.xhtml?persistentId=doi:10.7910/DVN/AKDIHF

### RESOLVED: test split renamed to test_indistribution.csv
The test split has been renamed from `test_unseen_generator.csv` to `test_indistribution.csv` to accurately reflect that it is an in-distribution evaluation (same SD v1.4 generator as training). This is no longer a blocker. Once GenImage is available, a true unseen-generator test split can be created by holding out a generator (e.g., Midjourney) entirely from training.

### AMBIGUITY 1: CIFAKE 32×32 vs. real-world deployment
CIFAKE images are 32×32 pixels (CIFAR-10 resolution). Real-world AI-generated images are typically 512×512 or larger. A detector trained only on CIFAKE will likely not generalise to high-resolution synthetic images. This should be documented in any reported results.

### AMBIGUITY 2: UnbiasedGenImage metadata.csv not included
The bias-correction metadata (JPEG quality factor, dimensions per image) mentioned in the UnbiasedGenImage paper is available only from Harvard Dataverse, not in the ZIP. If downloaded, it would enable JPEG-bias-aware training — recommended per the paper.
